hailort.log 해설:

최신 로그에서는 FW Control Opcode가 텍스트 이름으로 함께 표시되어, 각 단계별로 디바이스와 호스트가 어떤 상호작용을 하는지 명확하게 확인할 수 있습니다. 
주요 이벤트 순서는 다음과 같습니다.

1. 초기화 및 장치 확인 (Initialization)
    HAILO_CONTROL_OPCODE_IDENTIFY: 드라이버가 장치에 접속하여 펌웨어 및 프로토콜 버전을 확인합니다.
    HAILO_CONTROL_OPCODE_GET_DEVICE_INFORMATION: 장치의 세부 하드웨어 정보를 조회합니다.

2. 컨텍스트 및 앱 설정 (Configuration)
    HAILO_CONTROL_OPCODE_CHANGE_CONTEXT_SWITCH_STATUS: 컨텍스트 스위치 상태를 변경합니다 (초기화나 활성화 준비).
    HAILO_CONTROL_OPCODE_CONTEXT_SWITCH_CLEAR_CONFIGURED_APPS: 이전에 설정된 애플리케이션 정보를 지우고 깨끗한 상태를 만듭니다.
    HAILO_CONTROL_OPCODE_GET_HW_CONSTS: 하드웨어 상수값들을 읽어옵니다. (로그에서 여러 번 반복 확인됨)

3. 모델 네트워크 구성 (Model Loading)
    이 부분이 모델 로딩의 핵심입니다. 대량의 데이터가 전송되는 시점입니다.
    HAILO_CONTROL_OPCODE_CONTEXT_SWITCH_SET_NETWORK_GROUP_HEADER: 네트워크 그룹의 헤더 정보(메타데이터)를 설정합니다.
    HAILO_CONTROL_OPCODE_CONTEXT_SWITCH_SET_CONTEXT_INFO: 실제 모델의 컨텍스트 정보(Layer 구성, 파라미터 등)를 전송합니다.
    로그를 보면 len=585, len=1092, len=1500 등 다양한 크기의 데이터 패킷이 연달아 전송되는 것을 볼 수 있습니다. 
    이것이 바로 모델이 장치로 로드되는 과정입니다.

4. 추론 실행 (Inference Execution)
    모델 로딩 후 실제 데이터가 오고 가는 단계입니다.
    Launch transfer [H2D]: 호스트에서 디바이스로 입력 이미지 데이터(150,528 bytes)를 전송합니다.
    Launch transfer [D2H]: 디바이스에서 호스트로 추론 결과 데이터(1,000 bytes, Classification 결과)를 받아옵니다.
    이 과정이 입력 이미지 수만큼 반복됩니다.

5. 종료 및 정리 (Shutdown)
    HAILO_CONTROL_OPCODE_CHANGE_CONTEXT_SWITCH_STATUS: 컨텍스트 스위치 상태를 변경(비활성화)합니다.
    HAILO_CONTROL_OPCODE_CONTEXT_SWITCH_CLEAR_CONFIGURED_APPS: 설정된 앱 정보를 삭제합니다.
    vdma_buffer_unmap: 사용했던 메모리 버퍼들을 해제(Unmap)합니다.

요약: 
로그를 통해 장치 인식 
-> 초기화 
-> 모델 데이터 전송(Context Info) 
-> 추론 데이터 입출력(H2D/D2H) 
-> 정리
로 이어지는 전체 라이프사이클이 명확히 드러나고 있습니다. 특히 0x21 (SET_CONTEXT_INFO) 명령이 실제 모델을 칩에 "쓰는" 역할을 한다는 점이 확인되었습니다.
